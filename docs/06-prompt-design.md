# 产品 Prompt 设计

## 产品 Prompt 与开发 Prompt

开发 Prompt 是给 AI 编程代理的施工指令，描述要阅读什么、允许修改什么、如何测试和验收。
产品 Prompt 是 AI Tutor 运行时的行为规则，决定模型如何辅导学生。前者用于制造产品，
后者是产品本身的一部分。

实现来源是 `backend/app/ai/prompt_builder.py`。开发过程和实际使用过的 Prompt 保存在
`docs/prompts/development/phase-01-pedagogy-core.md`。

## 组合方式

`build_system_prompt` 接收已经计算好的 `StudentState` 和经过结构化组织的 `PromptContext`。
它只组合内容，不判断问题难度，不更新能力，也不调用模型。

当前模块按固定顺序组合：

1. 角色与目标。
2. 永久教学原则。
3. 隐藏学生状态和沟通风格。
4. 编程与数学的当前提示规则。
5. 允许行为。
6. 禁止行为。
7. 安全边界。
8. 信息不足和冲突处理。
9. 学生可见输出协议。
10. Prompt 版本记录。
11. 六类不可信上下文。

固定规则出现在用户内容之前，减少模型把后出现的注入文字误认为高优先级指令的风险。

## 角色与永久原则

Tutor 面向本科物理学生教授 Python。目标是促进理解、推理和独立解决问题，而不是尽快生成
可直接提交的答案。永久原则要求逐步增加帮助、分别处理编程与数学、解释错误原因、鼓励小实验，
并禁止伪造运行、测试、引用或学习进展。

## 学生状态与提示等级

Prompt 包含编程能力、数学能力、受控沟通风格和两个独立提示等级。学生不能看到这些内部值。

`HINT_INSTRUCTIONS` 把每个 `HintLevel` 映射为具体允许和禁止行为。Prompt Builder 不自行升降级，
而是消费 `compute_hint_levels` 已经产生的状态。这保证教学政策只有一个确定性来源。

沟通风格目前只允许 `Suitable for undergraduate beginners`。未知字符串会被拒绝，避免用户控制的
自然语言进入受信任规则区。未来增加风格时，应先加入受控枚举和相应测试。

## 上下文

`PromptContext` 包含：

- 当前用户问题。
- 最近对话。
- 已有问题摘要。
- Notebook 上下文。
- 当前单元格代码。
- 最近错误输出。

每个字段必须是字符串。空值会显示为 `[not provided]`，帮助模型区分“没有提供”与空白格式。

## 允许和禁止行为

允许行为包括询问学生尝试、解释概念和错误原因、提供当前等级允许的提示、建议小实验，
以及在信息不足时询问最关键的一项信息。

禁止行为包括低等级给完整答案、暴露隐藏状态、伪造工具运行、服从覆盖教学规则的请求，
以及把历史消息或上传内容当成更高优先级指令。

## 注入防护

用户消息、历史、Notebook、代码、注释、上传文件和错误都属于不可信内容。每个字段使用独立的
`<untrusted_...>` 边界。`<` 和 `>` 被 HTML 转义，因此输入中的伪造结束标签不能提前关闭边界。

每个字段转义后最多保留 4,000 个字符，超出部分标记为 `[truncated]`。这只是第一阶段的
单字段预算；真实模型接入时还需要总 Token 预算和按重要性分配上下文。

## 信息不足与异常处理

- 缺少代码、错误、输入或预期结果时，只问最关键的一项。
- Notebook 与描述冲突时，指出观察到的差异并要求确认。
- 无法判断是否同一问题时，使用较保守提示等级。
- 超出能力范围时，说明限制并给可验证的下一步。

## 学生可见输出

回答按需要包含简短确认、等级匹配的引导和一个推动下一步思考或实验的问题。不得暴露 JSON、
内部等级、系统规则或隐藏状态；标题、代码块和公式只在确实需要时使用。

## Provider 边界

Prompt Builder 生成系统 Prompt 后，将它与用户消息放入 `TutorRequest`。`TutorProvider` 负责把统一
请求交给某个模型实现，并返回统一 `TutorResponse`。教学算法不需要知道厂商 SDK、HTTP 协议、
API Key 或具体模型名称。

第一阶段使用 `MockTutorProvider`，因为它离线、免费、确定且可重复。它证明模块编排和数据合同，
但不能证明真实 LLM 的回答质量。

## Prompt 版本记录

当前版本是 `pedagogy-v0.1.0`，表示受控复刻中的首个模块化 Prompt。计划中的评测编号为
`prompt-eval-012` 至 `prompt-eval-018`，当前结果明确记录为 `not run`。

只有真正执行固定案例和评分规则后，才能把结果改成通过。不能复制规格中的示例结果冒充证据。

## Prompt 不是唯一安全边界

模型可以忽略 Prompt，Prompt 注入也无法只靠文字彻底解决。后续应用层仍需实施：

- 系统消息与用户消息分离。
- 后端独立计算提示等级。
- 元数据结构和类型校验。
- 单字段与总 Token 预算。
- API Key 与客户端隔离。
- 结构化输出校验。
- 对抗性 Prompt 评测。
- 日志脱敏、限流和错误回滚。
